# Refresh and portable backup validation — October 15, 2026

The refresh investigation reproduced serial house downloads and catalogue discovery stopping on the first bad detail. Cached metadata previously required a SQLite connection for every unique identity. The old local toy cache contained 381 known and 754 pending entries; these aggregate counts were read through a read-only SQLite connection. No production database or credential file was changed.

The implementation uses three concurrent house downloads, four concurrent realm/toy/item requests, one bulk metadata cache connection, and serial persistence. Normal refresh classifies decor from official item details rather than crawling the entire catalogue. Toy discovery drains successive bounded batches, retains partial progress, isolates missing details, and stops new work on global authentication/rate-limit failures. The same stop applies to house downloads and metadata jobs. Conditional revalidation retains upstream timestamps and reuses the existing raw archive without loading it.

Deterministic barriers verify worker limits, shared identity deduplication, the 100 planned metadata lookup budget per buying house, serial cache writes, queue deferral, retained snapshots, and failure isolation.
